# m5 主機群（RTX 4090）

MDgen 相關 GPU 工作優先用 m5 的兩台 4090；需要 L40S（48 GB）或大量分片時才用 Slurm HPC（[README](README.md)）。

## 主機

| 主機 | 連線 | GPU | 用途 |
| :--- | :--- | :--- | :--- |
| `m5813`（跳板） | 本機 `ssh m5813`（jeff@140.112.13.54:6666） | RTX 2060 SUPER 8 GB | 前處理、小測試 |
| `m5-cluster1` | 在 m5813 內 `ssh m5-cluster1` | RTX 4090 24 GB | 訓練、生成 |
| `m5-cluster2` | 在 m5813 內 `ssh m5-cluster2` | RTX 4090 24 GB | 訓練、生成 |

沒有 Slurm／PBS，`scripts/hpc_run.py` 不適用；長任務一律在節點上用具名 tmux（`tmux new -s jeff_<任務>`），`CUDA_VISIBLE_DEVICES=0`，輸出導到 log。帳號與實驗室共用，啟動前先 `nvidia-smi` 確認無人佔用顯存；預計佔用 4090 超過 24 小時先在群組報備；DataLoader `num_workers` 不超過 16。

## 路徑與環境（2026-11-06 實測，原始輸出見 [m5-2026-11-06.log](m5-2026-11-06.log)）

- 主存放：code 與 checkpoint 以 m5813 的 `/mnt/hdd2/tou` 為準。節點沒有 `/mnt/hdd2`，執行時把 code `rsync` 到節點的 `/mnt/hdd/jeff/tou` 再跑；完成的 checkpoint `rsync` 回 `m5813:/mnt/hdd2/tou`，確認後刪掉節點上的副本。暫存放 `/mnt/hdd/jeff/tou/tmp`，用完清掉。cache 導到大硬碟：`HF_HOME=/mnt/hdd/jeff/.cache/huggingface`、`TORCH_HOME=/mnt/hdd/jeff/.cache/torch`。
- 空間：cluster1 `/mnt/hdd` 剩 362G、cluster2 剩 431G；m5813 `/mnt/hdd` 剩 136G（85%），`/mnt/hdd2` 剩 2.0T（只有 m5813 有）。大型 checkpoint／軌跡定期移到 NAS。
- Conda：節點上的 env 在 `/home/jeff/.conda/envs/`（`mdgen`、`mdgen2026`、`mdgen2026-r2-a6-cu126` 等），base 在 `/opt/miniconda3`。`mdgen` env 為 torch 2.0.1+cu118，兩台皆 `torch.cuda.is_available() == True`。
- 節點間傳檔用 `rsync -avP`（m5813 ↔ m5-cluster*，已設免密碼），在 m5813 上執行：
  - 送 code：`rsync -avP /mnt/hdd2/tou/<專案>/ m5-cluster1:/mnt/hdd/jeff/tou/<專案>/`
  - 取回 checkpoint：`rsync -avP m5-cluster1:/mnt/hdd/jeff/tou/<專案>/checkpoints/ /mnt/hdd2/tou/<專案>/checkpoints/`

## 已踩過的坑

- 從 Windows 經 m5813 跳到節點時，`ssh` 不加 `-n` 或以 stdin 灌腳本（`Get-Content | ssh ... bash -s`）會卡住無輸出。做法：`scp` 腳本到 m5813，再 `ssh -n m5813 "bash /tmp/<腳本>"`；腳本內跳節點的 `ssh` 加 `</dev/null`。
- 遠端指令含引號或括號時，PowerShell 會先解析報錯；一律寫成 LF 腳本檔再傳。
